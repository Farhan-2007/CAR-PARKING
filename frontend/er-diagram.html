ER Diagram & Relational Schema

Database design for the ParkEasy Car Parking Management System.

1. Entity-Relationship Diagram

Entities are rectangles, attributes are ovals, relationships are diamonds, and 1:N labels indicate cardinality.

Entity Attribute Relationship 1 / N Cardinality

PK = Primary Key; FK = Foreign Key. The diagram represents the USERS, SLOTS, BOOKINGS and PAYMENTS tables in the project database.

2. Relational Schema

PK = Primary Key · FK = Foreign Key · UNIQUE = Candidate/alternate key constraint.

USERS

Attribute Data Type Key Constraint
id SERIAL PK Auto-generated
username VARCHAR(50) UNIQUE NOT NULL
password_hash VARCHAR(64) — NOT NULL
is_admin BOOLEAN — NOT NULL, DEFAULT FALSE

SLOTS

Attribute Data Type Key Constraint
id SERIAL PK Auto-generated
status VARCHAR(20) — NOT NULL, DEFAULT 'AVAILABLE'; AVAILABLE or BOOKED

BOOKINGS

Attribute Data Type Key Constraint
id SERIAL PK Auto-generated
username VARCHAR(50) FK References USERS(username), NOT NULL
slot_id INT FK References SLOTS(id), NOT NULL
amount DECIMAL(10,2) — NOT NULL, non-negative
status VARCHAR(20) — NOT NULL
created_at TIMESTAMP — DEFAULT CURRENT_TIMESTAMP

PAYMENTS

Attribute Data Type Key Constraint
id SERIAL PK Auto-generated
booking_id INT FK References BOOKINGS(id), NOT NULL
amount DECIMAL(10,2) — NOT NULL, non-negative
status VARCHAR(20) — NOT NULL
paid_at TIMESTAMP — Payment timestamp
Relationships and cardinality
USERS (1) — (N) BOOKINGS: one user can make multiple bookings.
SLOTS (1) — (N) BOOKINGS: a slot can appear in multiple bookings over time.
BOOKINGS (1) — (N) PAYMENTS: a booking can have multiple payment records.
Foreign keys maintain referential integrity between the tables.
